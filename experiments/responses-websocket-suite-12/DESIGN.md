# Twelve-task subagent evaluation

The primary question is whether allowing GPT-6.1 Sol to choose native delegation improves task outcomes compared with the same model working alone. The evaluation uses direct Responses API WebSocket protocol calls, no OpenAI/Agents SDK, and no requested child count or depth. Native mode adds the discretionary availability paragraph; the common task, evidence, schema and controls are identical. A native-enabled run that chooses no child remains a valid observation, never filtered out or retried.

Twelve demo tasks comprise four workload profiles in each of operations, procurement and planning. Compact cases can reasonably favor a single agent. Independent cases have separable branch/vendor/hub calculations. Large cases increase source volume, entity count or optimization possibilities. Uncertain cases contain incomplete ledgers, unavailable contractual commitments or a provably infeasible complete inspector plan. Neither arm is required to delegate to earn a passing score. These are constructed demo workloads, not production episodes or twelve independent real organizations.

All source packs and private answer keys are generated before paid calls. The answer keys are calculated from raw sources with Decimal rounding, then independently replayed with integer arithmetic for accounting and pricing; scheduling is checked with topological evaluation/exhaustive assignments and an independent DFS/permutation solver. Perfect answers and deliberately wrong/missing/unsupported/duplicate output variants calibrate deterministic scoring. No external human label reviewer or semantic citation judge is claimed. Tools can only read hash-verified source IDs; hidden labels and arbitrary files are inaccessible.

Quality includes exact factual values, findings precision/recall/F1, required source-ID coverage, null preservation, critical decision accuracy and strict task success. Structural source coverage measures required IDs and nonempty explanations, not semantic entailment or writing quality. Strict success requires every factual/expected finding and structural source check, valid case/decision, and no invalid IDs, duplicates or extra facts. Do not call equal factual scores equal total answer quality.

Each case has five matched pairs, 60 pairs and 120 admissions total. Pair order alternates and the case/repetition schedule is deterministically shuffled. At most two pairs are in flight, with sequential arms inside each pair; one fresh WebSocket per assessment. Concurrent service load and cache behavior are recorded limitations. Service/backend conditions and model-selected work graphs are not controlled. There are no model retries or replacement assessments; failures remain in reliability denominators and missing usage remains unknown.

The collector uses immediate function-result injection for native mode and same-socket response-create continuation for ordinary single mode. It retains completed nonempty root reports across responses, ignores child finals as root answers, deduplicates function calls and output items, and drains pending injection acknowledgments after response completion. Hosted collaboration actions are API-owned. Native concurrency three is an API setting; depth three below root and twelve total agents are instruction ceilings with observed-violation stops, not hard native creation limits.

Per-attempt observation bounds are 600 seconds, twelve responses, 32,768 output tokens and USD0.90 returned-usage estimate. The whole suite has USD25 returned-usage admission allowance with conservative reservations for pending pairs and unknown usage. These are client observer/admission limits, not provider invoice caps. Standard frozen token rates per million are input2/cached0.10/cache-write2.50/output10 USD. Unique returned response usage is priced once; reasoning is included in output, and no child token estimate is added. Full native-tree billing is not independently invoice reconciled.

Analysis retains all attempts, per-case distributions, successful-both paired ratios and completed-only quality/time/cost views with denominators. Overall summaries weight each of the twelve cases equally; five repeats of one case do not become five independent cases. Exploratory benefit thresholds are frozen in the manifest, including citation coverage and critical decision checks; no winner-only reporting. Five pairs per case remain limited evidence for variability, rare failures or generalization.

This evaluation compares the two configurations on the twelve tasks distributed here. Both arms use WebSocket; it does not compare HTTP and WebSocket performance.
